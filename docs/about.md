# 職務経歴

## 職務要約

2017年4月から2025年8月までの8年5か月間、株式会社AdvanCE Japanにてシステム開発に従事しました。

**JavaとRDB・SQLを中心としたバックエンド開発**を専門とし、業務要件をデータモデルや処理方式に落とし込む設計から、中核となる処理の実装まで担当してきました。

主に損害保険分野で、既存システムの保守、基幹システムの刷新、新規システムの構築を経験しました。また、情報銀行システムの新規構築では、統計データAPIなどの要件定義・設計を担当しました。

キャリア初期は詳細設計・実装・テストを中心に担当し、その後はサブシステムの要件定義・設計、チームリーダーとしての設計方針策定やコードレビュー、開発・テスト方法の改善などへ担当範囲を広げてきました。

また、社内DX推進室のリーダーとして、業務改善の方針策定、コーポレートサイトの刷新、若手メンバーへの技術指導にも取り組みました。

具体的な使用技術と経験範囲については、[技術スタック]({{ '/skills/' | relative_url }})にまとめています。

### 損害保険・保険募集管理システムの新規構築
{: id="損害保険保険募集管理システムの新規構築"}

**2024年4月〜2025年8月**

#### プロジェクト概要
{: id="プロジェクト概要"}

損害保険の保険募集管理システムを新規構築するプロジェクトに参画しました。

ノーコード開発基盤を中心とするシステムで、自社チームは主に、標準機能では対応できない要件を実現するためのバックエンド・フロントエンド開発を担当しました。プロジェクトの途中からは、ノーコード開発基盤を用いた画面開発も担当しました。

私は自社チームの技術面で、実装方針の検討、共通処理の構築、難易度の高い機能の実装、メンバーへの技術支援・レビューなどを担当しました。

進捗管理や作業割り当てを担当するリーダーは別におり、私自身は主に技術面を担当していました。

#### 主な担当業務
{: id="主な担当業務"}

**バックエンドの初期構築・開発方針の整備**

- Spring Boot・MyBatisを使用したバックエンドプロジェクトの初期構築
- 実際のDBテーブルを対象とするデータ登録・参照用サンプルAPIとテストコードの実装
- 例外の種類に応じたHTTPステータスコード・レスポンス形式の共通化
- 個人情報などの機密情報をアプリケーションログへ不用意に出力しないための共通処理の実装
- OpenAPI Specificationを使用したAPIインターフェース定義方針の提案・導入

サンプルAPIは、実際のテーブルの一部のカラムを登録・参照する形で作成し、後続の機能開発の実装例として利用できるようにしました。

その後、担当メンバーが全カラムに対応する処理を追加し、本番アプリケーションの一部として採用されました。例外応答の共通化やログ出力制御など、自身が実装した共通処理も本番アプリケーションに組み込まれました。

**業務機能・共通機能の設計・実装**

- Redisを利用したセッション管理、アクセストークンの更新を含む認証・認可処理の設計・実装
- APIやデータへのアクセス権限制御の設計・実装
- 既存システムとのSOAP連携処理の実装
- Spring Shellを用いた運用向けCLIの実装

**開発支援・レビュー**

- バックエンドメンバーの設計・コードレビュー
- 技術的な問題の調査、実装方針の検討、メンバーへの説明
- フロントエンド開発の技術支援、一部機能の実装・改修
- ノーコード開発基盤による、顧客が作成した仕様に基づく画面実装・調整

### 損害保険関連システムの新規構築・追加開発
{: id="損害保険関連システムの新規構築追加開発"}

**2021年1月〜2023年3月**

#### プロジェクト概要
{: id="プロジェクト概要-1"}

損害保険の契約情報を扱い、外部システムとのデータ連携や各種バッチ処理を行うシステムの構築に参画しました。

2021年1月からの先行開発では、設計・実装担当として開発からリリースに向けた対応まで携わりました。

2022年3月からの追加開発では、約4名のチームのリーダーとして、外部システムとの契約情報連携を中心に設計方針の策定・中核処理の実装・メンバーのレビューを担当しました。

#### 先行開発：2021年1月〜2022年2月
{: id="先行開発2021年1月2022年2月"}

**主な担当業務**

- 月次集計バッチ処理の設計・実装
- サブシステム内の結合試験や、関連サブシステムとの結合試験への対応
- 運用担当者向けの手順書作成、リリースに向けた準備

要件定義の終盤から設計工程にかけて参画し、主にバックエンド・バッチ処理を担当しました。

開発だけでなく、テスト結果の確認や運用手順の整備にも取り組みました。

**開発基盤の整備**

この先行開発では、機能開発に加えて、開発メンバーが共通の手順で作業できるよう、開発基盤の整備にも取り組みました。

- Gitのブランチ戦略・運用ルールの策定
- AWS CodeStarを利用したCI環境の構築
- Gitの基本操作やブランチ運用、プルリクエストの作成方法などのメンバーへの共有・指導

#### 追加開発：2022年3月〜2023年3月
{: id="追加開発2022年3月2023年3月"}

**主な担当業務**

- 外部システムとの契約情報連携に関する設計方針の策定
- データモデル、SQL、Spring Batchによる中核処理の設計・実装
- メンバーが担当した詳細設計・実装内容のレビュー
- 関連する他チームの設計レビュー
- Integration Testを重視するテスト方針の策定・導入
- 複数年にわたる日次バッチ処理のローカル自動テストの構築
- シナリオテストの検証方針見直し、実行・確認作業の効率化

**契約情報連携バッチの設計・実装**

契約情報の変更や外部システムからの応答によって必要な処理が変わる機能について、当初の方法では設計が難航していたため、DBに蓄積した情報から必要な処理を導出する方式を提案しました。

この方針が採用され、データモデル・SQL・Spring Batchの中核となる処理を自身で設計・実装しました。

その他の処理はメンバーと分担し、設計・コードレビューを行いました。

**Integration Testを重視するテスト方針への変更**

追加開発では、チームリーダーとして、自チームのテスト方針を見直しました。

従来は、テスト対象クラスの依存先をモック化するクラス単体テストに重点が置かれていました。しかし、内部のクラス構成を変更するとテストコードも大幅に修正する必要があり、リファクタリングが難しくなる問題がありました。

そこで、内部実装への依存が少ないIntegration Testを重視する方針を採用しました。

JUnit・DbUnit・LocalStackなどを組み合わせ、外部連携を含む複数年分の日次バッチ処理をローカル環境で自動検証する仕組みも構築しました。

**シナリオテストの効率化**

AWS環境で実施するシナリオテストでは、途中からテストリーダーを引き継ぎ、検証方法の見直しと実行手順・検証資料の効率化を担当しました。

すべての日付のバッチ実行は維持しながら、詳細な業務検証を必要なイベント日に集中する方針を採用しました。

AWS CLIによる実行スクリプトとExcelによる検証テンプレートを作成し、担当メンバーと分担して約5年間の日次処理を用いたシナリオテストを進めました。

### 情報銀行システムの新規構築
{: id="情報銀行システムの新規構築"}

**2020年5月〜2020年12月**

#### プロジェクト概要
{: id="プロジェクト概要-2"}

情報銀行システムの新規構築プロジェクトに参画しました。

同システムが外部の企業に対して提供する、ランキングなどの統計データAPIや、そのためのデータ集計・管理機能を中心に担当しました。

当初はPM補佐として参画し、途中から複数サブシステムの主担当として、要件定義・設計・技術検証・協力会社の成果物レビューなどを行いました。

#### 主な担当業務
{: id="主な担当業務-2"}

**統計データAPIの要件定義・設計**

- 7種類の統計データAPIのインターフェース設計
- 統計・ランキングなどを取得するSQLの設計
- DWHから集計済みデータをデータマートへ反映する方式の設計
- APIの契約管理機能の設計

統計データを取得するSQLは、テーブル名・カラム名などを物理名で記述し、そのままプログラムに組み込める水準まで具体化しました。

一方、APIの入力条件に応じてWHERE句の条件を動的に切り替える処理や、SQLをアプリケーションへ組み込む作業は協力会社が担当しました。

**データマート更新方式の技術検証**

大量のデータを保持するDWHへAPIから直接問い合わせるのではなく、あらかじめ集計したデータマートから応答する構成を検討しました。

データマートの更新時にAPIの利用を妨げないよう、PostgreSQLのパーティション機能を利用した更新方式を設計しました。

この方式については、自身でPythonとPostgreSQLを用いたプロトタイプを作成し、データの集計・取込・パーティション追加などの動作を検証したうえで、設計書に反映しました。

本番向けの更新処理の実装・テストは協力会社が担当しました。

**AWS構成設計・技術レビュー**

- API Gateway、Lambda、Aurora PostgreSQL、Glueなどを組み合わせたアプリケーション構成の設計
- AWSリソースの設定値やセキュリティグループ等の設計
- Redshiftの特性を考慮したデータベース設計レビュー
- 他サブシステムを含む要件・設計の横断的なレビュー
- 協力会社が実装したコードのレビュー、指摘事項の修正確認

AWSリソースの実際の構築やCloudFormationによる環境構築は協力会社が担当しました。
